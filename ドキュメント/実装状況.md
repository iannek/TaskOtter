# TaskOtter 要件別の実装状況

確認日：2026-10-02  
対象：[要件.md](要件.md) 第1～6節・第8節。第7節の将来候補と第10節の設計・運用事項も別に整理する。

現在のソースコード、テストコード、[既存の検証記録](../docs/verification.md) を照合した記録である。初回文書作成時にはテストを再実行していない。2026-10-02の追加要望反映時には型チェック・ビルド・自動テスト・ブラウザテストを再実行した。実機の確認は利用者の報告に基づき、開発環境の検証とは区別して記載する。

## 1. 現在の到達点

Task・Outcomeの登録・編集・削除、ダッシュボード、階層一覧・Outcomeカード、ガント、カレンダー、JSON保存と外部更新の読み込み、不正データ時の保存禁止を実装した。初版の機能要件について、ソース確認で未実装と判定した項目はない。

ただし、初版の全要件を実際の利用環境で満たすと確認できた段階ではない。MacのApple containerでの起動・画面確認は利用者が2026-10-02に実施済み。Windowsでのビルド・起動、Mac／Windowsの保存・LANからの接続禁止・性能測定は確認が残っている。Macの停止・再開や保存の動作まで確認済みとは扱わない。

| 状態 | この文書での意味 |
| --- | --- |
| 実装済み | 要件に対応する処理・画面がソースに存在する。全操作・全ブラウザの検証完了を意味しない |
| 実装済み・実機未検証 | 定義・スクリプト・処理はあるが、対象のMac／Windows環境で動作確認できていない |
| 開発環境で確認済み・実機未検証 | Linux開発環境で測定・検証したが、要件にある実際の保存先での確認が残る |
| 未実装・将来候補 | 第7節にある、初版では追加しない候補 |
| 対象外 | 要件で初版に含めないと指定された機能、またはツール外の運用 |

### 5.3 ガントチャート

主な実装は [Gantt.svelte](../src/frontend/components/Gantt.svelte) と [Editor.svelte](../src/frontend/components/Editor.svelte)。

| 要件 | 状態 | 実装した内容 |
| --- | --- | --- |
| Outcomeの独立した期間と、子Taskの予定期間 | 実装済み | 親子それぞれのデータから別々のバーを表示 |
| 未紐づけTaskのまとまり | 実装済み | Outcomeなしの親行の下に表示 |
| 期間未設定のTask・Outcomeはバーなしの行 | 実装済み | 行は残し、期間バーを作らない |
| Task選択でサイドバーから期間・締切等を編集 | 実装済み | 行のTask名またはバーから共通編集フォームを開く |

| 名前・ステータス・カテゴリの表示順 | 実装済み | 各Outcome内の子Taskを選んだ項目でソート |
| 表示中にも期間外が分かる | 実装済み | 警告記号とバーの色で表示 |

日付見出しはカレンダーの週表示と同じM/D(曜)形式。表示期間は1週間・2週間・1ヶ月・日付指定から選択可能。初期は月曜始まりの2週間。前後のボタンは選択した期間単位で移動する。表示範囲の外へ続くTaskのバー端を角なしで表現する。日付指定で任意の開始・終了へ移動できる。長い期間は横スクロールに対応。拡大縮小と親行の折り畳みは追加していない。

### 5.4 カレンダー

主な実装は [Calendar.svelte](../src/frontend/components/Calendar.svelte)、重複予定の配置は [model.ts](../src/shared/model.ts)。

| 要件 | 状態 | 実装した内容 |
| --- | --- | --- |
| 日・週・月表示、週は日曜始まり | 実装済み | 日は1列、週は7列、月は日曜始まりの7列×6週 |
| 日・週は日付が横、0:00～24:00が縦 | 実装済み | 1時間96pxの時間軸。縦スクロールで全時間帯を表示 |
| 次の対応予定を開始から終了まで表示 | 実装済み | 開始時刻から上位置、所要時間から高さを計算 |
| 締切日と次の対応予定をそれぞれ表示 | 実装済み | 月表示では別イベント。日・週の締切は各日付列の上部に表示 |
| Doneは通常非表示、フィルターを外せば表示 | 実装済み | 「Doneも表示」のチェックで切り替え |

前後移動と「今日」ボタンも実装した。重複予定は横に分け、多数重なると列幅を広げて横スクロールにする。月表示では件数による省略をせず、セルを伸ばして全件表示する。

## 7. 性能・検証（要件第6節）

状態は **開発環境で確認済み・実機未検証**。500件のTask・20件のOutcomeをLinux ARM64の一時保存先に置き、Chromium（1440×1000）で確認した。実際のWindows／Macのホスト保存先を使った測定は行っていない。

| 操作 | 開発環境の測定値 | 要件の上限 |
| --- | --- | --- |
| 起動済みアプリを開いて500件の階層一覧を確認するまで | 約209 ms | 5秒 |
| Task・Outcome切り替え | 約82 ms | 5秒 |
| ガント切り替え | 約96 ms | 5秒 |
| カレンダー切り替え | 約116 ms | 5秒 |
| ダッシュボード切り替え | 約136 ms | 5秒 |

これは単一実行の参考値であり、コンテナのビルド・起動時間は含まない。操作性の体感評価、異なる実機・ブラウザ、日・週表示での大量重複予定の性能測定は別途必要。全てのデータ形状で5秒以内と保証する測定ではない。

| 検証 | 記録済みの結果 | 対象 |
| --- | --- | --- |
| npm run check | エラー0・警告0 | Svelte・TypeScriptの型チェック |
| npm run build | 成功 | 画面とNode APIの本番用ファイル生成。コンテナイメージのビルドとは別 |
| npm test | 42件成功 | データ仕様・期間・完了条件・JSON保存・API・保存失敗時の保護 |
| npm run test:e2e | 8件成功 | 主要画面操作・外部データ異常からの復旧・フィルター・重複配置・500件性能 |
| 起動スクリプトのsh -n | 成功 | シェル構文のみ。CLIでの実行確認ではない |
| npm audit | 確認時点で脆弱性0件 | ロックファイルの依存関係。アプリ全体の安全性を保証する検証ではない |

テストの根拠：[業務ルール](../tests/rules.test.ts)、[保存・API](../tests/storage-api.test.ts)、[ブラウザ操作](../tests/browser/app.spec.ts)。詳しい環境・手順は [検証記録](../docs/verification.md) を参照。

日／週の予定の中央で全体を移動し、上端／下端で開始／終了を直接変更する。専用ハンドルは撤去。月の予定は時刻・長さを維持して日付を移動する。締切日は週の上部欄・月の日付マス間で移動し、次の対応予定・期間・ステータスは維持する。日表示の締切移動と、週の時間帯への締切ドロップは対象外。

設定の15分／30分を共用し、プレビュー、逆転防止、Escape・対象外ドロップ、端の自動スクロール、直前1件の取り消しに対応。ドロップで既存APIへ保存する。未確定のドラッグや保存拒否で業務データを書き換えず、取り消しでは最新のTaskに変更前の日時だけを適用する。同じ日時が後から編集された場合は古い取り消しを無効化する。ドラッグと取り消しは既存の日時・概要履歴に記録される。

主な実装は[Calendar.svelte](../src/frontend/components/Calendar.svelte)、時間の丸めと端の調整は[calendar.ts](../src/shared/calendar.ts)。依存追加・保存Schema・API・起動スクリプトの変更なし。操作は[カレンダーの操作](../docs/calendar.md)を参照。第8節の未実装候補から直接追加・移動を除外した。
