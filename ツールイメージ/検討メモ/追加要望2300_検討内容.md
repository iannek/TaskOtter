# 23:00の追加要望：修正版イメージ

[サンプルHTML](追加要望2300_画面案.html)をブラウザで開いてください。サーバー・ビルド・外部ライブラリ・フォント取得は不要です。画像の出力は行いません。

## 反映した案

| 要望 | 画面案 |
| --- | --- |
| ダッシュボード／カレンダーのTask追加位置 | 4画面共通でページ見出し右側に＋Outcomeと＋Taskを並べる |
| Outcome行からTask追加の記号 | ＋を行の先頭に配置。押すとOutcomeを選択済みの新規Taskサイドバーを開く |
| Outcomeの優先度を削除 | Outcome詳細に優先度欄を置かない |
| Outcomeの完了欄を移動 | 「詳細を編集」の横に完了チェックを置く。未完了Taskがある場合は無効 |
| 行先頭のOUTCOME／TASKを削除 | 種別ラベルを置かず、親の青い背景と子の字下げで区別 |
| Outcome後のTask件数を削除 | 親行の件数を非表示 |
| TaskのチェックとDoneを連動 | Taskの先頭にチェックを追加。ステータス選択との相互反映をサンプル内で操作可能 |
| Outcomeなしを常時表示 | 未分類Taskが0件でも親行を表示 |
| Outcome行の「進行中」を削除 | 親行は名前と期間のみ。完了時は完了の表示を残す案 |
| Task追加の表記 | 「＋ Task」に統一 |
| ガントを月／日2段へ | 上段を年月ごとの結合セル、下段を日だけの列とする。月境界に縦線を配置 |

初期はガントの2週間表示で9月28日～10月11日を描き、月またぎを確認できます。1週間・2週間・1ヶ月を切り替え、前後へ移動できます。土日は背景色、今日相当のサンプル日（10月2日）は青で区別します。任意期間の入力は今回のサンプルでは省略しています。

左メニューで4画面を切り替えます。「Doneも表示」を付けると完了チェックとステータスの同期を確認しやすくなります。チェックを外した場合は直前の未完了ステータスに戻す案です。外部JSON等で直前の状態が分からない場合はInboxへ戻す想定ですが、この戻し方は実装前の検討事項です。

Task詳細は合意済みの「基本情報 → メモ → 資料リンク → 関連チャット」を維持した簡易表示です。前回の[Markdownメモ案](タスク詳細_タブとMarkdown案.html)でもメモの表示を確認できます。今回のHTMLは23:00の表示変更を中心としたサンプルで、全項目の保存動作やMarkdownの全機能を再実装したものではありません。

操作結果はサンプルのメモリ内だけに反映され、再読み込みで戻ります。アプリ本体・依存関係・保存JSON・要件ドキュメントの実装状況は変更していません。Outcome優先度の既存データの扱いは本実装時に整理します。


## 一覧の列配置を調整

件名列は上限320pxとし、すぐ右にステータスを配置。長い件名をサンプルに入れ、最大2行で省略する。件名にマウスを重ねると標準ツールチップで全文を表示し、詳細の入力欄にも省略なしの文字列を渡す。狭い画面では件名列の上限を160pxへ縮め、期間等の右側の列は横スクロールで確認する。Task一覧を初期画面に変更した。

Outcome行・Task行・見出しに共通の列幅を使用し、対応予定期間の左端を揃えた。親行の＋は先頭、親名はチェック欄から件名欄にかけて配置し、子の件名はその右へ字下げしている。カード／ダッシュボードではチェック欄の後ろに余分な字下げ用の空欄を作らない。


## 既存の日時項目を復元

一覧を簡略化する際に省略してしまっていた締切日・次の対応予定を復元。対応予定期間の右に、締切日、次の対応予定（日付と開始〜終了時刻）を配置した。Task詳細の基本情報にも締切日・予定日・開始／終了時刻を戻し、次の予定で行うことと一緒に表示する。狭い画面は右方向への横スクロールで全項目を確認できる。Outcomeの期間はTaskの対応予定期間と同じ列を維持する。


## 日付の曜日表示

一覧の対応予定期間・締切日・次の対応予定をM/D(曜)に統一し、Outcomeの期間も揃えた。詳細の各日付はYYYY/M/D(曜)を表示。入力からサンプル内部へ反映するときはYYYY-MM-DDへ戻す。期間・締切のホバーで年付きの表記を確認できる。ガントの下段は合意どおり日だけを表示し、日付のホバーに曜日を付ける。
