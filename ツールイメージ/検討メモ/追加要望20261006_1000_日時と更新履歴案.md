# 作成・更新日時と変更概要の履歴案

2026/10/06 10:00の追加要望と、会話で合意した「日時と変更概要だけの履歴」を反映したHTML案。前回承認された画面を複製し、既存のダッシュボード・カレンダーの日／週／月、折りたたみ、末尾の追加行を維持する。アプリ本体・依存・保存JSONは変更しない。

- サイドメニューのWORKSPACE、上部のWorkspace /を削除。「ローカルワークスペース」も「ローカルデータ」に変更。
- Task・Outcomeの詳細ヘッダーに、読み取り専用の作成日時と最終更新日時を配置。タブを切り替えても見える。
- Taskは基本情報 → メモ → 資料リンク → 関連チャット → 履歴。Outcomeは基本情報 → 履歴。
- 履歴タブは新しい順で日時と変更概要を表示。日時は端末のタイムゾーン、曜日付き。保存値の案はUTC。
- 概要は差分から定型文で生成する。AI要約ではない。ステータス・日付等は変更前後、長いメモ・名前・作業内容は変更の有無、資料・チャット・サブタスクは追加／削除件数や変更を表示する。
- 一度の保存を一つの履歴にまとめ、内容が変わらない保存、閲覧・折りたたみ・タブ移動には記録を作らない。
- 新規は作成・更新日時を自動設定して作成記録を残す。既存の日時・履歴がないデータは「不明」「履歴はまだありません」と表示し、作成日時を推測しない。
- Task変更に伴うOutcome完了解除も、Outcome側の変更として記録する案。
- この方式は変更前の長文全文を保存せず、復元機能も含まない。外部JSON直接編集の記録は対象外。実装時はAPI保存時にサーバーで確定する。

確認方法：長い件名の最初のTaskは日時と複数の履歴あり。「集計データを確認する」と「次期の運用計画を整理する」は旧データとして日時・履歴なし。新規追加でも自動記録予定の表示を確認できる。保存、ステータス選択、完了チェックはサンプル内の履歴へ反映する。データはメモリ上だけで、再読み込みで戻る。

作成時刻・更新時刻・履歴データを今のJSONに任意項目として追加する実装案。既存データとの互換性、履歴件数・概要長の上限などは本体実装時に定義する。HTML案は既存の簡易メモ・資料フォームの範囲であり、サーバー保存や実際のMarkdown部品を変更するものではない。
